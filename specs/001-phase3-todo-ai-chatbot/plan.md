# Implementation Plan: Phase III Todo AI Chatbot

**Branch**: `001-phase3-todo-ai-chatbot` | **Date**: 2026-02-09 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-phase3-todo-ai-chatbot/spec.md`

## Summary

Add a conversational AI chatbot interface to the existing Phase II todo application. Users manage tasks through natural language via a ChatKit UI. The backend uses OpenAI Agents SDK to process messages and delegates task operations to an MCP server (stdio transport) exposing 5 tools (`add_task`, `list_tasks`, `complete_task`, `delete_task`, `update_task`). Conversations and messages are persisted to the database for stateless, multi-turn interaction.

## Technical Context

**Language/Version**: Python 3.13+ (backend), TypeScript (frontend)
**Primary Dependencies**: FastAPI, SQLModel, `openai-agents`, `mcp[cli]` (backend); Next.js 15, `@openai/chatkit-react` (frontend)
**Storage**: Neon Serverless PostgreSQL (existing) + 2 new tables: `conversation`, `message`
**Testing**: `pytest` via `uv run pytest` (Red-Green-Refactor)
**Target Platform**: Linux server (WSL2 dev), Vercel (frontend), uvicorn (backend)
**Project Type**: Web application (monorepo: backend + frontend)
**Performance Goals**: 90% of chat requests < 3 seconds (SC-003)
**Constraints**: Stateless server (no in-memory session state), gpt-4o-mini model, 2000 char message limit
**Scale/Scope**: Demo load, single-user concurrent interaction

## Component Design

### Backend Components

#### 1. MCP Server (`src/mcp/server.py`)
- Uses `mcp` package with `FastMCP` decorator pattern
- Defines 5 tools: `add_task`, `list_tasks`, `complete_task`, `delete_task`, `update_task`
- Each tool accepts `user_id` as first parameter for isolation
- Tools create their own DB sessions (separate process from FastAPI)
- Runs as stdio subprocess invoked by OpenAI Agents SDK
- Database URL passed via environment variable

#### 2. Chat Service (`src/services/chat_service.py`)
- Orchestrates: receive message -> load history -> run agent -> store response
- Creates `MCPServerStdio` context with `uv run src/mcp/server.py`
- Creates `Agent` with instructions including user_id context
- Uses `Runner.run()` for async agent execution
- Manages conversation lifecycle (create if new, load if existing)
- Handles OpenAI API errors gracefully (store user message, return error)

#### 3. Chat Route (`src/api/routes/chat.py`)
- `POST /api/chat` — accepts `ChatRequest`, returns `ChatResponse`
- Validates message length (1-2000 chars)
- Validates conversation ownership (if `conversation_id` provided)
- Injects `CurrentUser` via existing JWT dependency
- Delegates to `ChatService`

#### 4. New Models (`src/db/models/conversation.py`, `src/db/models/message.py`)
- `Conversation`: UUID PK, owner_user_id, created_at
- `Message`: int PK, conversation_id FK, role, content, created_at
- Auto-created by `SQLModel.metadata.create_all()` on startup

#### 5. Config Update (`src/config.py`)
- Add `openai_api_key` field to `Settings`
- Read from `OPENAI_API_KEY` env var

### Frontend Components

#### 6. ChatKit Proxy Route (`src/app/api/chatkit/route.ts`)
- Next.js API route at `/api/chatkit`
- Translates ChatKit format (OpenAI Chat Completions) to our `POST /api/chat` format
- Forwards JWT from request headers
- Translates response back to OpenAI format for ChatKit

#### 7. Chat Page (`src/app/chat/page.tsx`)
- Uses `useChatKit` hook from `@openai/chatkit-react`
- Self-hosted mode pointing to `/api/chatkit`
- Custom fetch injects JWT Bearer token from Better Auth
- Glassmorphism styling consistent with Phase II design

### Integration Flow

```
User types message in ChatKit UI
  → ChatKit calls POST /api/chatkit (Next.js proxy)
    → Proxy extracts message, forwards to POST /api/chat (FastAPI)
      → Chat route validates input + auth
        → ChatService loads conversation history from DB
        → ChatService stores user message
        → ChatService creates MCPServerStdio subprocess
        → ChatService creates Agent with MCP tools
        → Agent (gpt-4o-mini) processes message, invokes MCP tools
        → MCP tools execute task operations against DB
        → Agent returns natural language response
        → ChatService stores assistant message
      → Chat route returns response
    → Proxy translates to OpenAI format
  → ChatKit displays response
```
